# Test Implementation

## Порядок работы

1. Изучи составленные тестовые сценарии.
2. Изучи `AGENTS.md` и структуру текущего проекта.
3. В зависимости от задачи: напиши автотест по тестовым сценариям, запусти отладку, исправь и проверь автотест.
4. После написания или исправления автотеста, запусти его и проверь, что он работоспособен.
5. В случае падения теста проанализируй причину, исправь и перезапусти для проверки.
6. Если после первой итерации исправлений тест остается нерабочим, прерви работу и спроси пользователя
   о дальнейших шагах. Не уходи в бесконечный цикл запусков и доработок. Предоставь пользователю в диалоге
   полную информацию о проблеме, которую удалось собрать, и предложения по дальнейшим шагам.
7. Запускай только тесты, над которыми работаешь. Не запускай полный набор тестов без явного указания пользователя.

## Размещение новых автотестов в проекте

1. Все тесты находятся внутри папки `tests/`.
2. Тесты на один и тот же раздел API в Swagger должны находится в одном файле.
3. Новый тест дописывай в существующий файл, если файл для данного раздела уже есть.
4. Создавай новый файл для теста, если файла для данного раздела еще нет.
5. Группируй тесты по Python-классам. Каждый тест - метод Python-класса.

## Требования к автотестам

1. Соблюдай структуру проекта, описанную в `AGENTS.md`.
2. Работай только с существующим техническим стеком проекта. Не подключай новые библиотеки, инструменты, утилиты.
3. Старайся делать минимально необходимый набор изменений.
4. Все API-запросы в тестах должны выполняться через API-клиент `src/api_practice/api_client/api_client.py`.
   Если требуемых для автотеста запросов не хватает в API-клиенте, допиши нужные методы.
5. Модели данных для API описываются с помощью Pydantic классов.
   Не работай с JSON напрямую в виде строк, всегда используй сериализацию и десериализацию.
6. Добавляй только необходимую тесту функциональность, не добавляй ничего "на будущее".
7. Не выполняй рефакторинг по ходу написания автотестов.
8. Используй параметризацию в автотестах, где это применимо и имеет смысл.
9. Используй Allure-декораторы в автотестах и методах API-клиента.

## Пример кода автотеста

```python
@allure.suite("Работа с инсулиновой помпой")
@allure.sub_suite("Статус и управление инсулиновой помпой")
class TestPumps:

    @allure.title("Запрос статуса помпы {pump_id}")
    @allure.description("Запрашиваем статус помпы и проверяем статус-код 200 и тело ответа.")
    def test_get_status(self, api_client: ApiClient, pump_id: str):
        response = api_client.get_status(pump_id)

        response_data = GetStatusResponse.model_validate(response.json())

        with allure.step("Проверка статус-кода и тела ответа"):
            assert response.status_code == 200
            assert response_data == off_pump_get_status_response()
```
