# Test Design

## Порядок работы

1. Изучи endpoint, который требуется покрыть автотестами,
   по спецификации [Swagger](https://ips.alexgallax-edu.ru/docs).
   Если endpoint не найден, не пытайся его придумать или искать похожий.
   Явно скажи об этом пользователю и спроси, чтоб делать дальше.
2. Составь набор тестовых сценариев для необходимого и достаточного покрытия endpoint.
3. Если какой-то инофрмации не хватает для составления сценария, не придумывай и не пытайся угадать.
   Спроси пользователя о дальнейших шагах.

## Техники тест-дизайна

Обязательно используй техники тест-дизайна при проектировании сценариев:
1. Классы эквивалентности и граничные значения: учитывай их в переборах параметров для API-запросов.
2. Описывай позитивные (как правило 2xx коды ответа) и негативные проверки
   (4xx, 5xx коды ответа, невалидные значения в запросе).
3. Не делай примитивного перебора большого количества значений в лоб, используй техники тест-дизайна,
   чтобы определить их необходимое и достаточное количество.
4. Покрывай тестами только существующую функциональность, не делай тесты "на будущее",
   не пытайся предполагать, как endpoint будет меняться потом. Используй фактическую актуальную информацию.
